# One mount module behind the Window and the Pop-up

A Window and a Pop-up are different things — the Window cascades, only one per Feature may be open, and one of them is active; the Pop-up has none of that — but both need the same mechanical job done: create a component, put it into the document at a chosen element, configure it, and later take it away. That job is one module, and it stays ignorant of everything the Window owns. Its interface is the smallest thing that does it: a component, a target `Element` and the bindings that configure it, in exchange for a handle whose single `destroy()` leaves the target exactly as it was found. Two thin callers sit above it — the Window host, which keeps the cascade index, the at-most-one rule and the active Window and sets `--cascade-n` on the element it mounts, and the Pop-up host, which owns nothing. The Desktop provides its bounds element as a value rather than being found by a document lookup. The trade-off: a reader who expects the Window and the Pop-up to be independent finds shared machinery and has to learn why; in exchange the mounting, the configuration and the teardown exist once, and two paths that had already drifted apart in their teardown, their ordering and their mounting idiom cannot drift again.
